# RDM002 Blueprint and ROM001 Dropdown Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix ROM001's preset dropdown (label-display bug, alphabetical-instead-of-panel ordering), add helper-naming guidance text, generalize the generator script to target multiple blueprint files, and add a new Hue Tap Dial Switch (RDM002) blueprint that reuses the same shared preset list.

**Architecture:** The existing `scripts/generate_scene_presets_options.py` gains category-declaration-order sorting (replacing alphabetical) and a list of target blueprint files (replacing a single hardcoded path) — both blueprints splice the identical generated option block into their own marker pair via the existing, unchanged `splice_generated_block`. RDM002 is a new, structurally simpler blueprint (no hold, no direction helper) built from verified real `zha_event` payload shapes, not inferred from ROM001's pattern.

**Tech Stack:** Python 3 standard library only (unchanged). YAML anchors/aliases for shared option lists (unchanged mechanism, now used within two separate files independently).

## Global Constraints

- No dependencies beyond the Python standard library.
- `blueprint.homeassistant.min_version` is `2024.10.0` for both blueprints — verified sufficient for every selector/feature used (same `select` selector as before; RDM002 introduces no selector types beyond what ROM001 already uses).
- Blueprint input *keys* on ROM001 (`preset_short`, `preset_double`, `direction_helper`, etc.) must not change — only the `preset_short`/`preset_double` selector's `custom_value`/`sort` properties and `direction_helper`'s description text change.
- The generator script only ever rewrites text strictly between each file's own `# BEGIN generated scene_presets options` / `# END generated scene_presets options` marker lines.
- All option labels/values are rendered via `json.dumps(..., ensure_ascii=False)` (unchanged from the prior fix).
- Dropping `custom_value: true` is a deliberate, already-approved trade-off: it fixes the label-display bug (confirmed root cause: `ha-selector-select.ts`'s `custom_value` path never wires a `valueRenderer`, so the closed field shows the raw stored value, not the label) at the cost of the "type a raw ID for a preset that isn't in the list" escape hatch.
- RDM002's button-hold events (`button_N_hold`) are never used, and no blueprint-side filtering of the dial's `step_with_on_off` event is added beyond what the upstream quirk already does — both are deliberate, per the design doc's investigated ceiling (upstream zigpy/zha-device-handlers#3696: held buttons emit an event indistinguishable from a real left dial-turn; the quirk's own partial filter is the only mitigation, and it is documented via comment, not duplicated).
- Everything in the repo is in English.

```markdown
### Hue Tap Dial Switch (RDM002) via ZHA

Controller for the Philips Hue Tap Dial Switch, paired through ZHA.

| Action | Behaviour |
| --- | --- |
| Short press (any button) | Applies that button's preset |
| Double press (any button) | Applies that button's second preset, if configured |
| Dial rotation | Adjusts brightness; spin speed controls step size |

[![Open your Home Assistant instance and show the blueprint import dialog with a specific blueprint pre-filled.](https://my.home-assistant.io/badges/blueprint_import.svg)](https://my.home-assistant.io/redirect/blueprint_import/?blueprint_url=https%3A%2F%2Fgithub.com%2Fmosart%2Fhome-assistant-blueprints%2Fblob%2Fmain%2Fcontrollers%2Fhue_tap_dial_rdm002%2Fhue_tap_dial_rdm002.yaml)

#### Requirements

- The remote paired via **ZHA**. Zigbee2MQTT and deCONZ are not supported;
  the blueprint listens for `zha_event` directly.
- The [`scene_presets`](https://github.com/Hypfer/hass-scene_presets) custom
  integration, installed through HACS.

Unlike the Smart Button blueprint above, no toggle helper or reference
entity is needed — the dial reports real, absolute rotation direction, so
there's no internal state to track between triggers.

#### Choosing presets

Same picker as the Smart Button blueprint above — see "Choosing presets"
there. Each button's double-press field can be left blank to do nothing on
double press.

#### Notes on behaviour

Holding a button is not supported. On this device, a held button reports an
event that looks identical to turning the dial left — a known upstream
limitation ([zigpy/zha-device-handlers#3696](https://github.com/zigpy/zha-device-handlers/issues/3696))
that the device's quirk only partially filters. Short press, double press,
and dial rotation are unaffected.

Clicking the dial itself (as opposed to turning it) is not exposed to Home
Assistant at all — the device's ZHA quirk discards that event before it
becomes visible, so it can't be used in any blueprint built on ZHA.
```
